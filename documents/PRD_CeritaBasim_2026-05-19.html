1 · Overview & Goals

Produk. Cerita Basim adalah situs personal di cerita.basim.id yang menggabungkan portfolio project dan blog editorial dalam satu domain. Pembaca dapat membaca cerita, mengeksplorasi project, memberi komentar dan reaksi, serta berlangganan newsletter — semua tanpa membuat akun, paywall, atau iklan.

Goals:

  • G1. Owned audience — Basim memiliki konten, URL, dan email list.
  • G2. Performansi premium — Lighthouse 95+ di setiap halaman, FCP <1s di Indonesia.
  • G3. Engagement berkualitas — komentar yang dimoderasi, reaksi ringan, newsletter plain-text.
  • G4. Operasi $0/bulan — sepenuhnya di dalam free tier Cloudflare + Resend untuk 1.500 subscriber pertama.
  • G5. Workflow menulis sederhana — markdown di Git, deploy otomatis via push.

Non-goals (v1.0): monetisasi, multi-author, paid membership, mobile app, search beyond client-side filter, comments dengan rich-text editor.

2 · Scope

In scope (v1.0)

  • Home page (hero, featured project, latest posts)
  • Project index + detail (case study)
  • Blog index + filter + tag/category
  • Blog post detail (TOC, reading progress, related posts)
  • About page
  • Komentar threaded (1 level reply) dengan moderasi
  • Reaksi emoji (5 jenis, anonymous)
  • Newsletter subscribe + double opt-in
  • Newsletter dispatch (manual trigger per post)
  • Admin dashboard ringan (login, moderasi komentar, analytics, subscriber list)
  • RSS feed
  • Sitemap + structured data (Article schema)
  • Dark mode toggle (system + manual)
  • Cloudflare Turnstile untuk anti-spam

Out of scope (v1.0)

  • Payment / membership tier
  • Multi-author / role permission
  • WYSIWYG editor (markdown only)
  • Server-side rendering untuk konten primer (selalu static)
  • Internationalization (i18n) — single language (ID + occasional EN inline)
  • Mobile native app
  • Komentar dengan rich text / image upload
  • Full-text search (gunakan client-side filter v1)
  • OAuth login (komentar tetap dengan email + nama)

4 · User Stories

US-1 · Membaca cerita

Sebagai Salsa, saya ingin membaca cerita panjang tanpa interupsi popup atau paywall, supaya saya bisa fokus pada isi dan menyelesaikannya dalam satu sesi.

Acceptance criteria:

  • Halaman post dimuat <1s di koneksi 4G Indonesia.
  • Tidak ada modal/popup yang muncul kecuali user secara eksplisit klik "subscribe".
  • Indikator progress baca tampil di top bar.
  • Daftar isi (TOC) generated otomatis dari heading h2/h3 dan sticky di desktop.
  • Reading time estimate ditampilkan di header post.

US-2 · Menjelajahi project

Sebagai Rio, saya ingin melihat semua project Basim di satu halaman dan filter berdasarkan kategori, supaya saya bisa cepat menilai kemampuan teknis sesuai kebutuhan saya.

  • Halaman /karya menampilkan semua project sebagai grid kartu.
  • Filter pill: All, Web, Mobile, Tools, Eksperimen.
  • Setiap kartu menampilkan: hero image, judul, tagline, kategori, tahun.
  • Klik kartu → halaman detail case study dengan: ringkasan, problem, proses, hasil, link demo/repo.

US-3 · Memberi komentar

Sebagai Salsa, saya ingin meninggalkan komentar tanpa harus membuat akun, supaya tidak ada friction.

  • Form komentar minta: nama (required), email (required, tidak ditampilkan publik), isi komentar (required, markdown ringan, max 2.000 karakter).
  • Cloudflare Turnstile dipasang sebelum submit.
  • Komentar pertama dari email baru → masuk antrian moderasi (status: pending).
  • Komentar berikutnya dari email yang sudah disetujui → tampil otomatis (status: approved).
  • Reply 1 level threading, max 1 nested reply.
  • Markdown ringan: bold, italic, link, code inline. Tidak ada image, tidak ada heading.

US-4 · Berlangganan newsletter

Sebagai Salsa, saya ingin tahu kalau ada cerita baru tanpa harus cek website, supaya tidak ketinggalan.

  • Halaman /subscribe dan inline form di footer setiap post.
  • Hanya minta alamat email + checkbox consent.
  • Double opt-in: email konfirmasi dikirim, klik link → subscriber active.
  • Setiap email ada link unsubscribe dengan token unik.
  • Konfirmasi visual setelah submit: "Cek email kamu untuk konfirmasi".

US-5 · Memberi reaksi

Sebagai Salsa, saya ingin memberi tanggapan ringan tanpa harus menulis komentar.

  • Bar reaksi di bawah post: 5 emoji (❤️ love, 💡 insightful, 🔥 fire, 🤔 thinking, 👏 applause).
  • Counter di bawah setiap emoji.
  • Anonim — disimpan via fingerprint (IP hash + UA hash, bukan cookie). Satu fingerprint bisa kasih max 1 reaksi per emoji per post.
  • Animasi bounce saat klik.

US-6 · Publish post baru (admin)

Sebagai Basim, saya ingin publish cerita baru dalam <5 menit dari draft sampai live.

  • Tulis markdown (.mdx) di folder src/content/posts/.
  • Frontmatter wajib: title, description, publishedAt, tags[], cover.
  • git push → Cloudflare Pages build & deploy otomatis dalam <90 detik.
  • Setelah deploy, admin dashboard menampilkan tombol "Send newsletter for this post" dengan preview rendering.
  • Klik kirim → batch email dikirim via Resend, progress bar menampilkan jumlah sent/queued.

US-7 · Moderasi komentar (admin)

Sebagai Basim, saya ingin meninjau komentar pending di satu tempat tanpa membuka tiap post.

  • Halaman /admin/moderation menampilkan daftar komentar pending, terbaru di atas.
  • Untuk setiap komentar: konten, nama, email (masked), post terkait, timestamp, tombol approve/reject/spam.
  • Bulk action: select multiple → approve/reject sekaligus.
  • Saat approve email pertama dari user baru, sistem otomatis whitelist email tersebut untuk komentar berikutnya.
  • Email notification ke Basim saat ada komentar pending baru (digest 1× per hari).

5 · Requirements (EARS Format)

Format EARS: When/While/Where <trigger>, the <system> shall <action>.

5.1 Konten & Reading

REQ-001 · MUST When pembaca membuka URL /cerita/{slug} yang valid, the sistem shall menampilkan halaman post statis dalam <1 detik (FCP) di koneksi 4G dari Indonesia.
REQ-002 · MUST When pembaca membuka URL post yang tidak ada, the sistem shall menampilkan halaman 404 kustom dengan rekomendasi 3 post terkait.
REQ-003 · MUST While pembaca scroll halaman post, the sistem shall menampilkan progress bar di bagian atas viewport yang merefleksikan persentase scroll dari konten artikel.
REQ-004 · MUST When halaman post di-render, the sistem shall menghasilkan daftar isi (TOC) otomatis dari heading h2 dan h3, dengan anchor link yang berfungsi.
REQ-005 · SHOULD When pembaca menyelesaikan satu post (scroll >90%), the sistem shall menampilkan 3 rekomendasi post terkait berdasarkan kesamaan tag.

5.2 Komentar

REQ-010 · MUST When pembaca submit komentar pertama dengan email yang belum pernah dipakai, the sistem shall menyimpan komentar dengan status pending dan tidak menampilkannya secara publik.
REQ-011 · MUST When admin menyetujui komentar pertama dari sebuah email, the sistem shall menambahkan email tersebut ke daftar trusted, sehingga komentar berikutnya dari email itu auto-approve.
REQ-012 · MUST When pembaca submit komentar, the sistem shall memverifikasi token Cloudflare Turnstile sebelum memproses request. Token tidak valid = HTTP 403.
REQ-013 · MUST When komentar disimpan, the sistem shall menyaring konten untuk pola spam umum (URL berulang, kata-kata blacklist) dan tag otomatis sebagai spam bila ditemukan.
REQ-014 · SHOULD When komentar reply diapprove, the sistem shall mengirim email notifikasi ke parent commenter (jika opt-in).

5.3 Reaksi

REQ-020 · MUST When pembaca klik tombol reaksi, the sistem shall mencatat reaksi dengan kunci unik (post_id, emoji, fingerprint_hash); klik kedua dari fingerprint sama untuk emoji sama akan menghapus reaksi (toggle).
REQ-021 · MUST When count reaksi diminta, the sistem shall mengembalikan response dalam <200ms (read dari KV cache).

5.4 Newsletter

REQ-030 · MUST When user submit form subscribe, the sistem shall menyimpan email dengan status unconfirmed dan mengirim email konfirmasi dalam <30 detik.
REQ-031 · MUST When user klik link konfirmasi yang valid (token belum kedaluwarsa, <7 hari), the sistem shall mengubah status email ke active dan menampilkan halaman terima kasih.
REQ-032 · MUST When user klik link unsubscribe yang valid, the sistem shall mengubah status ke unsubscribed dalam satu klik (no confirmation page required) dan tidak akan mengirim email lagi.
REQ-033 · MUST When admin men-trigger dispatch newsletter untuk sebuah post, the sistem shall mengirim email ke semua subscriber active dalam batch 100 email per detik (rate limit Resend) dan menampilkan progress real-time.
REQ-034 · SHOULD When dispatch gagal di tengah jalan, the sistem shall menyimpan state batch terakhir yang berhasil sehingga retry tidak mengirim duplikat.

5.5 Admin

REQ-040 · MUST When Basim mengakses /admin/*, the sistem shall memverifikasi session via Cloudflare Access (email magic link ke alamat di allowlist). Tidak ada session = redirect ke login.
REQ-041 · MUST When Basim membuka /admin/moderation, the sistem shall menampilkan komentar status pending diurutkan dari terbaru, dengan tombol approve/reject/spam dan dukungan bulk action.
REQ-042 · MUST When ada komentar pending baru, the sistem shall mengirim digest email ke Basim 1× per hari (atau immediate jika >5 pending).

5.6 Performance & Operations

REQ-050 · MUST Where halaman static (home, /karya, /cerita, post detail), the sistem shall mencapai Lighthouse score ≥95 di Performance, Accessibility, Best Practices, dan SEO pada test desktop dan mobile.
REQ-051 · MUST When commit di-push ke branch main, the sistem shall auto-build dan deploy ke production dalam <90 detik.
REQ-052 · MUST While beroperasi normal dengan traffic <10.000 pageview/bulan dan 1.500 subscriber, the sistem shall tetap dalam Cloudflare free tier (D1, KV, Workers, Pages) dan Resend free tier.

7 · Technical Architecture

Arsitektur static-first: konten primer di-render saat build, interaksi dinamis (komentar, reaksi, subscribe) lewat Cloudflare Workers. Semua di dalam free tier.

Stack pilihan

LayerPilihanJustifikasi
FrameworkAstro 5Zero-JS by default, content collection untuk markdown, islands untuk komponen interaktif. Sudah ditentukan user.
HostingCloudflare PagesUnlimited deploy + bandwidth, edge cache global, custom domain gratis.
Konten primerMarkdown di GitOwned, version-controlled, deploy lewat push. Tidak butuh CMS.
DatabaseCloudflare D1 (SQLite)5GB free, sudah cukup untuk komentar+subscriber 5+ tahun. Lihat trade-off di FAQ internal PRFAQ.
Cache & counterCloudflare KV100k reads/day free; cocok untuk reaksi counter dan rate-limit.
Backend logicCloudflare Workers (via Astro adapter)Lightweight handler untuk endpoint POST komentar/subscribe/dispatch.
Email transactionalResend3.000 email/bulan free, API simple, deliverability bagus, TS SDK.
Auth adminCloudflare Access (Zero Trust)Magic link email ke allowlist, gratis untuk <50 user. Tidak perlu kelola password.
Anti-spamCloudflare TurnstilePrivacy-friendly CAPTCHA, gratis, no Google.
AnalyticsCloudflare Web AnalyticsCookieless, privacy-first, gratis.
Asset / imageCloudflare R2 + Astro ImageR2 free 10GB storage; otomatis dioptimasi via Astro Image untuk WebP/AVIF.
Storage backupCloudflare R2 (D1 dump weekly)Disaster recovery untuk komentar & subscriber list.

Catatan: AWS-native baseline vs Cloudflare

Steering file menyarankan stack AWS-native. Untuk produk ini, Cloudflare dipilih dengan justifikasi:

  1. Domain user (basim.id) sudah hosted di Cloudflare; pindah DNS = friction tidak perlu.
  2. User secara eksplisit memilih Astro + adapter Cloudflare di awal scoping.
  3. Free tier Cloudflare (Pages, D1, KV, Workers) memberi headroom 10× lebih besar dibanding AWS Free Tier untuk personal blog use case ini.
  4. Stack tetap migratable ke AWS (Lambda + DynamoDB + SES + Amplify) bila skala melonjak — Astro adapter agnostic.

Trade-off ini didokumentasikan di design.md spec.

8 · Data Model

SQLite schema di Cloudflare D1. Migrasi via wrangler d1 migrations.

-- comments table
CREATE TABLE comments (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  post_slug    TEXT NOT NULL,
  parent_id    INTEGER REFERENCES comments(id) ON DELETE CASCADE,
  display_name TEXT NOT NULL,
  email_hash   TEXT NOT NULL,        -- sha256(email + salt)
  email_enc    TEXT NOT NULL,        -- AES-encrypted, hanya admin bisa decrypt
  body_md      TEXT NOT NULL,
  status       TEXT NOT NULL,        -- pending|approved|rejected|spam
  ip_hash      TEXT,
  ua_hash      TEXT,
  created_at   INTEGER NOT NULL,     -- unix epoch ms
  approved_at  INTEGER
);
CREATE INDEX idx_comments_post   ON comments(post_slug, status, created_at);
CREATE INDEX idx_comments_status ON comments(status, created_at);

-- trusted emails (auto-approve setelah komentar pertama disetujui)
CREATE TABLE trusted_emails (
  email_hash   TEXT PRIMARY KEY,
  trusted_at   INTEGER NOT NULL,
  comment_id   INTEGER REFERENCES comments(id)
);

-- newsletter subscribers
CREATE TABLE subscribers (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  email        TEXT UNIQUE NOT NULL,
  status       TEXT NOT NULL,        -- unconfirmed|active|unsubscribed|bounced
  confirm_tok  TEXT,                 -- nullable setelah confirm
  unsub_tok    TEXT NOT NULL,        -- token unsub permanen
  source       TEXT,                 -- 'inline_post' | 'subscribe_page' | 'footer'
  created_at   INTEGER NOT NULL,
  confirmed_at INTEGER,
  unsubed_at   INTEGER
);
CREATE INDEX idx_subs_status ON subscribers(status);

-- newsletter dispatches
CREATE TABLE dispatches (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  post_slug    TEXT NOT NULL,
  triggered_at INTEGER NOT NULL,
  status       TEXT NOT NULL,        -- pending|sending|sent|failed
  total        INTEGER,
  sent         INTEGER DEFAULT 0,
  failed       INTEGER DEFAULT 0,
  cursor_id    INTEGER                 -- last subscriber id processed
);

-- KV keys (Cloudflare KV, no schema)
-- reactions:<post_slug>:<emoji>        -> count (number)
-- reactions:<post_slug>:<fp>:<emoji>   -> 1   (presence marker, TTL 1 year)
-- ratelimit:comment:<ip_hash>          -> count (TTL 60s)
-- ratelimit:subscribe:<ip_hash>        -> count (TTL 600s)

9 · API Surface

/api/commentsGET ?post=<slug> 200: { comments: [...], count } Hanya status=approved. Cached 30s di KV.

12 · Risks & Mitigations

RisikoLikelihoodImpactMitigation
Discoverability rendah (no algorithmic distribution)HighMediumSEO + structured data, syndicate selektif ke dev.to/Hashnode, share di sosial.
Spam komentar massiveMediumMediumTurnstile + rate limit + spam filter + first-comment moderation.
Burn out maintainingMediumHighStack stabil, fitur minim, metric dievaluasi 6/12 bulan, stop-loss didefinisikan di PRFAQ.
D1 outage atau perubahan pricingLowMediumKonten primer di Git (graceful degrade), backup R2 weekly, migration path ke SQLite/Turso siap.
Email deliverability buruk (ke Inbox spam)MediumMediumResend dengan SPF + DKIM + DMARC, plain text email, no tracking pixel, daftar warm-up perlahan.
Subscriber list bocorLowHighEmail enkripsi at-rest, akses admin di-gate Cloudflare Access, audit trail.
Build break setelah dependency updateMediumLowPin major versions, Renovate weekly PR, preview deploy test sebelum merge.
